#### Snippet 1: Static Variable Declaration vs Definition
```cpp
class Demo {
    static int x;
public:
    void show() { cout << x; }
};
int main() {
    Demo d;
    d.show();
}
```
* **Output**: **Compilation / Linker Error** (`undefined reference to Demo::x`).
* **Justification**: A `static` data member is only **declared** inside the class. It allocates zero memory until it is explicitly **defined at file scope** outside the class definition: `int Demo::x = 0;`. Without this definition, the linker cannot resolve the symbol `Demo::x`.

#### Snippet 2: Composition / Member Object Destructor Order
```cpp
class Engine {
public:
    ~Engine() { cout << "Engine destroyed "; }
};
class Car {
    Engine e;
public:
    ~Car() { cout << "Car destroyed "; }
};
int main() {
    Car c;
    return 0;
}
```
* **Output**: `Car destroyed Engine destroyed `
* **Justification**: In composition (containership), constructor execution goes from inside out (member objects first, then enclosing class), but **destructors execute in the exact reverse order**: the enclosing class destructor (`~Car()`) executes first, followed by the destructor of its member objects (`~Engine()`).

#### Snippet 3: Reference Overloading (`int&` vs `const int&`)
```cpp
void func(int &x) { x += 5; }
void func(const int &x) { cout << x << " "; }
int main() {
    int a = 10;
    func(a);
    cout << a;
}
```
* **Output**: `15`
* **Justification**: `a` is a non-const lvalue of type `int`. When calling `func(a)`, the compiler performs overload resolution. `int&` is an **exact match** for a non-const lvalue without requiring `const` qualification promotion. Therefore, `func(int&)` is invoked, modifying `a` from 10 to 15. The final `cout << a` prints `15`.

#### Snippet 4: Virtual vs Non-Virtual Dynamic Dispatch
```cpp
class Base {
public:
    virtual void f() { cout << "Base f "; }
    void g() { cout << "Base g "; }
};
class Derived : public Base {
public:
    void f() { cout << "Derived f "; }
    void g() { cout << "Derived g "; }
};
int main() {
    Base *b; Derived d;
    b = &d;
    b->f();
    b->g();
}
```
* **Output**: `Derived f Base g `
* **Justification**: 
  - `b->f()`: `f()` is declared `virtual` in `Base`. Hence, the call is resolved via **late/dynamic binding** through `d`'s VTABLE, invoking `Derived::f()`.
  - `b->g()`: `g()` is non-virtual. Hence, the call is resolved via **early/static binding** based on the static type of pointer `b` (`Base*`), invoking `Base::g()`.

#### Snippet 5: RTTI and `dynamic_cast` Sibling Mismatch
```cpp
class Base { virtual void func() {} };
class Derived : public Base {};
class Another : public Base {};
int main() {
    Base *b = new Another();
    Derived *d = dynamic_cast<Derived*>(b);
    if(d) cout << "Success";
    else cout << "Failed";
}
```
* **Output**: `Failed`
* **Justification**: `b` dynamically points to an instance of `Another`. When `dynamic_cast<Derived*>(b)` is executed, the runtime type checker inspects the RTTI metadata and determines that the underlying object is of type `Another`, not `Derived` (they are siblings in the inheritance hierarchy). For pointer types, a failed downcast returns `nullptr`, causing the `else` branch to execute and print `Failed`.

#### Snippet 6: File Extraction Operator Whitespace Delimitation
```cpp
ofstream fout("file.txt");
fout << "First";
fout.close();
fout.open("file.txt", ios::app);
fout << " Second";
fout.close();
ifstream fin("file.txt");
string s;
fin >> s;
cout << s;
```
* **Output**: `First`
* **Justification**: The file content after both writes is `"First Second"`. The formatted input extraction operator `fin >> s` skips leading whitespace and reads characters until the **first whitespace delimiter** (space, tab, or newline). Therefore, `fin >> s` reads only `"First"`. (To read the full line including the space and `"Second"`, `getline(fin, s)` would be required).

### 1. Dec 2025 Q1(a): Class TIME with Exception Handling for Test Duration
```cpp
#include <iostream>
#include <iomanip>
#include <stdexcept>
using namespace std;

class TimeException : public runtime_error {
public:
    TimeException(const string &msg) : runtime_error(msg) {}
};

class TIME {
private:
    int hours;
    int minutes;
    int seconds;

    void validate() const {
        if (hours < 0 || hours >= 24 || minutes < 0 || minutes >= 60 || seconds < 0 || seconds >= 60) {
            throw TimeException("Invalid Time Data: Hours must be 0-23, Minutes and Seconds must be 0-59.");
        }
    }

    int toTotalSeconds() const {
        return hours * 3600 + minutes * 60 + seconds;
    }

public:
    TIME(int h = 0, int m = 0, int s = 0) : hours(h), minutes(m), seconds(s) {
        validate();
    }

    void input(const string &label) {
        cout << "Enter " << label << " (HH MM SS): ";
        if (!(cin >> hours >> minutes >> seconds)) {
            throw TimeException("Input Error: Non-numeric values entered for time.");
        }
        validate();
    }

    TIME subtract(const TIME &start) const {
        int secCompletion = this->toTotalSeconds();
        int secStart = start.toTotalSeconds();

        if (secStart > secCompletion) {
            throw TimeException("Logical Error: Start time cannot be greater than Completion time.");
        }

        int diff = secCompletion - secStart;
        int h = diff / 3600;
        diff %= 3600;
        int m = diff / 60;
        int s = diff % 60;

        return TIME(h, m, s);
    }

    void display(const string &label) const {
        cout << label << ": " 
             << setfill('0') << setw(2) << hours << ":"
             << setfill('0') << setw(2) << minutes << ":"
             << setfill('0') << setw(2) << seconds << endl;
    }
};

int main() {
    try {
        TIME startTime, endTime;
        startTime.input("Test Start Time");
        endTime.input("Test Completion Time");

        TIME duration = endTime.subtract(startTime);
        duration.display("Total Test Duration");
    }
    catch (const TimeException &e) {
        cerr << "\n>>> EXCEPTION CAUGHT: " << e.what() << endl;
    }
    catch (const exception &e) {
        cerr << "\n>>> STANDARD EXCEPTION: " << e.what() << endl;
    }
    return 0;
}
```

```cpp
    y = p.getRadius() * sin(rad);

    p.display();

    // Invokes conversion constructor Rectangular(const Polar&)
    Rectangular r = p;
    r.display();
```

### 4. Sept 2025 Mid-Sem Q5: 3D Drone Navigation Simulation with `Vector3D`
```cpp
#include <iostream>
#include <cmath>
using namespace std;

class Vector3D {
private:
    double x, y, z;
public:
    Vector3D(double xVal = 0.0, double yVal = 0.0, double zVal = 0.0) : x(xVal), y(yVal), z(zVal) {}

    // Vector Addition (New Position = Current + Movement)
    Vector3D operator+(const Vector3D &other) const {
        return Vector3D(x + other.x, y + other.y, z + other.z);
    }

    // Vector Subtraction (Displacement = Final - Initial)
    Vector3D operator-(const Vector3D &other) const {
        return Vector3D(x - other.x, y - other.y, z - other.z);
    }

    // Dot Product (Scalar = v1 * v2)
    double operator*(const Vector3D &other) const {
        return (x * other.x) + (y * other.y) + (z * other.z);
    }

    // Magnitude / Distance from Origin
    double magnitude() const {
        return sqrt(x * x + y * y + z * z);
    }

    // Overloaded Stream Insertion << for Formatted Output
    friend ostream& operator<<(ostream &os, const Vector3D &v) {
        os << "(" << v.x << ", " << v.y << ", " << v.z << ")";
        return os;
    }
};

int main() {
    cout << "=== DRONE 3D NAVIGATION SIMULATOR ===" << endl;
    Vector3D initialPos(10.0, 20.0, 30.0);
    Vector3D movement(5.0, -10.0, 15.0);

    cout << "Initial Drone Position: " << initialPos << endl;
    cout << "Movement Vector:        " << movement << endl;

    // Vector Addition
    Vector3D finalPos = initialPos + movement;
    cout << "New Drone Position:     " << finalPos << endl;

    // Displacement from Origin
    double distFromOrigin = finalPos.magnitude();
    cout << "Distance from Origin:   " << distFromOrigin << " units" << endl;

    // Dot Product of Initial and Final Positions
    double dotProd = initialPos * finalPos;
    cout << "Dot Product (Init * Final): " << dotProd << endl;

    return 0;
}
```

```cpp
#include <iostream>
```

```cpp
class Address {
```

# SECTION 4: MASTER SOLUTIONS FOR CONCEPTUAL EXAM QUESTIONS

### 1. Pure Virtual Function Body (Dec 2025 Q2b-i)
* **Question**: Can a pure virtual function have a body/implementation inside and/or outside the class?
* **Answer**:
  - A pure virtual function **CANNOT** have a body **inside** the class declaration (syntax `virtual void f() = 0 { ... }` is illegal in C++).
  - However, a pure virtual function **CAN** have a body/implementation defined **outside** the class:
    ```cpp
    class Base {
    public:
        virtual void f() = 0; // Pure virtual declaration
    };
    void Base::f() { // Legal body outside class!
        cout << "Base default implementation" << endl;
    }
    ```
  - **Purpose**: It enforces that derived classes *must explicitly override* `f()`, while allowing the derived class to reuse the base implementation if needed by calling `Base::f();`.

---

### 2. Const Member Functions & Restrictions (Dec 2025 Q2b-ii)
* **Question**: What is a `const` member function in a class? What are its restrictions?
* **Answer**:
  - A member function declared with the `const` keyword suffix (e.g., `void display() const;`).
  - **Restrictions**:
    1. The implicit `this` pointer becomes `const ClassName* const`.
    2. It **cannot modify any non-static data members** of the calling object (unless marked `mutable`).
    3. It **cannot call any non-const member functions** of the same class (to prevent indirect modification).
    4. It guarantees read-only semantics and allows the function to be invoked on `const` objects.

---

### 3. Containership vs Inheritance (Dec 2025 Q2b-iii / Nov 2024 Q5a)
* **Question**: Can containership be used to achieve code reuse instead of inheritance?
* **Answer**:
  - **Yes**, via the principle of **Composition over Inheritance** ("Has-A" relationship).
  - Instead of deriving class `B` from `A` (`class B : public A`), class `B` declares an object of class `A` as a member (`class B { A objA; };`).
  - **Key Advantages**:
    1. **Looser Coupling**: Derived classes are not tightly bound to the internal representation of the base class.
    2. **Encapsulation Preservation**: The containing class cannot access private members of the contained class.
    3. **Dynamic Flexibility**: The contained object can be replaced or reconfigured at runtime.

---

### 4. `getline()` vs `>>` Operator for File Input (Dec 2025 Q2b-iv)
* **Comparison Table**:

| Feature | `fin >> variable` | `getline(fin, str)` |
| :--- | :--- | :--- |
| **Delimitation** | Stops at any whitespace (space, tab, `\n`) | Stops only at newline `\n` (or specified delimiter) |
| **Leading Whitespace** | Automatically skips leading whitespace | Does **not** skip leading whitespace; consumes it |
| **Spaces in Data** | Cannot read strings containing spaces | Reads complete strings containing spaces |
| **Delimiter Handling** | Leaves delimiter in the stream | Extracts and discards the delimiter `\n` |

### 5. Why `p + 1` Does Not Necessarily Increase Address by 1 Byte (Sept 2026 Q5a)
* **Answer**:
  - Pointer arithmetic in C++ is **type-scaled**.
  - When you evaluate `p + 1`, the actual byte increment is:
    $$\text{New Address} = \text{Current Address} + 1 \times \text{sizeof}(*p)$$
  - If `p` is an `int*` on a 64-bit architecture, `sizeof(int) = 4`, so `p + 1` increases the address by **4 bytes**.
  - It only increases by 1 byte if `p` is of type `char*` or `uint8_t*`.

---

### 6. Static Member Function vs Non-Static Data Access (Sept 2026 Q5b)
* **Answer**:
  - Non-static member functions receive an implicit `this` pointer pointing to the invoking object. Since static data members reside in the global/data segment and belong to the class, they are globally accessible to any member function.
  - In contrast, a **static member function is not invoked on any object and DOES NOT receive a `this` pointer**. Therefore, it has no object context to identify which instance's non-static data member it should access.

---

### 7. Memory Copies Count: `x`, `static y`, `const z`, `static const w` (Sept 2026 Q5c)
* **Answer**:
  - If 5 objects are created:
    - **`x`**: **5 copies** (1 per object $\implies$ belongs to object).
    - **`y` (`static int`)**: **1 copy** (shared across all instances $\implies$ belongs to class).
    - **`z` (`const int`)**: **5 copies** (each object has its own immutable constant initialized in constructor $\implies$ belongs to object).
    - **`w` (`static const int`)**: **1 copy** (shared immutable compile-time constant $\implies$ belongs to class).
