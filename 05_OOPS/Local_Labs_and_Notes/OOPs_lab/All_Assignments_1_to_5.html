#include <iostream> using namespace std; // In a comment, discuss whether this function is really a good candidate for the `inline` keyword: // This function is NOT a good candidate for the 'inline' keyword. // 1. The loop's length depends directly on input 'n'. As 'n' increases, the time spent executing // the loop dominates, rendering the minor savings of eliminating a function call insignificant. // 2. If called many times with different/large inputs, inlining duplicates the entire loop body // at each call site, causing substantial binary code bloat and reducing CPU instruction cache efficiency. // Compilers generally reject inlining requests for functions containing iterative loops. inline long long factorial(int n) { if (n < 0) return 0; long long fact = 1; for (int i = 1; i <= n; i++) { fact *= i; } return fact; } int main() { int val1 = 5, val2 = 8; cout << "Factorial of " << val1 << " = " << factorial(val1) << endl; cout << "Factorial of " << val2 << " = " << factorial(val2) << endl; return 0; }

Task 11. Write a friend function that directly modifies a private data member of a class object it's given (for example, resetting a Rectangle's length to zero).
In a comment, discuss the trade-off: since a friend function can freely read and modify private data from outside the class, does this weaken encapsulation? When might that trade-off still be worth it?
Ans -
#include <iostream> using namespace std; class Rectangle { private: double length; double width; public: void setDimensions(double l, double w) { length = l; width = w; } void display() const { cout << "Length: " << length << ", Width: " << width << endl; } // Friend function to modify private data friend void resetLength(Rectangle &r); }; // Friend function modifying private member 'length' directly void resetLength(Rectangle &r) { r.length = 0.0; } /* Comment: Discuss the trade-off: since a friend function can freely read and modify private data from outside the class, does this weaken encapsulation? When might that trade-off still be worth it? Trade-off Discussion: 1. Does it weaken encapsulation? Yes, friendship creates tight coupling between external functions and the internal data representation of a class. If private member variables change, friend functions must also be updated, which partially erodes the boundary of data hiding. 2. When is the trade-off worth it? - Operator Overloading: e.g., stream insertion/extraction operators `operator<<` and `operator>>`, where the left operand is `std::ostream` and cannot be a class member. - High-performance inter-class cooperation: When two closely related classes (e.g., Matrix and Vector, or Node and LinkedList) need direct access for performance without exposing public setters to the outside world. */ int main() { Rectangle rect; rect.setDimensions(12.0, 5.0); cout << "=== Before Friend Function Modification ===" << endl; rect.display(); resetLength(rect); cout << "\n=== After Friend Function Modification (Length Reset to 0) ===" << endl; rect.display(); return 0; }

Task 12. Write a class Student with private members for name and marks. Write a friend function that compares two Student objects and returns the one with higher marks. In main(), create a pointer to a 'Student' object, use it to access the object's data via the arrow operator, and pass the pointed-to object into your friend comparison function.
Ans -
#include <iostream> #include <string> using namespace std; class Student { private: string name; double marks; public: void setDetails(string n, double m) { name = n; marks = m; } string getName() const { return name; } double getMarks() const { return marks; } // Friend function to compare two Student objects friend Student getTopStudent(Student s1, Student s2); }; // Friend function definition Student getTopStudent(Student s1, Student s2) { if (s1.marks >= s2.marks) { return s1; } else { return s2; } } int main() { Student s1, s2; s1.setDetails("Aman", 88.5); s2.setDetails("Riya", 94.0); // Creating pointer to Student object Student* sptr = &s1; cout << "=== Accessing Student Data via Pointer and Arrow Operator (->) ===" << endl; cout << "Student 1 Name : " << sptr->getName() << endl; cout << "Student 1 Marks : " << sptr->getMarks() << endl; // Passing the pointed-to object (*sptr) into friend comparison function Student topper = getTopStudent(*sptr, s2); cout << "\n=== Top Student (Determined via Friend Function) ===" << endl; cout << "Name : " << topper.getName() << endl; cout << "Marks : " << topper.getMarks() << endl; return 0; }
